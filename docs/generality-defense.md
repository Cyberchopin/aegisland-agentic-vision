# 通用性证据及实际边界

本原型验证的是离线几何/质量启发式。没有通过测试推导真实飞行成功率，也没有证明可以完成
整条比赛路线。Gate A、tunnel、Gate B/chicane 和 landing 是使用场景，检测器中没有它们的
阶段编号、固定 waypoint、绝对比赛时间或现场像素坐标。

通用性来自以下可检查的约束，而非对未见场景的承诺。

| 约束 | 证据 | 仍依赖的假设 |
| --- | --- | --- |
| 坐标按图像/候选比例处理 | 线路、开口、pad 的缩放/平移参数化测试 | 地面线主要出现在配置的下部 ROI，开口近似正视 |
| 米制尺度由对齐深度和内参提供 | 72/74 列间隙边界测试、修改 envelope 的测试 | 内参/深度尺度正确；单探测平面不代表全路径 |
| 时间只用于新鲜度和同步 | 将所有时间平移 1000 秒、frame_index 改为 900，输出线路和间隙不变 | 回放提供同一时钟域的时间戳 |
| 低光必须有实测收益 | CLAHE 原始/重试得分、contrast gain 和 blackout 反例 | 对纹理、曝光和噪声的泛化尚未标定 |
| 未知不能成为空闲 | 零值、NaN、盲区、超量程、错时、过期、局部无深度测试 | 严格按列拒绝会牺牲召回率 |
| 落点需要独立拒绝条件 | 实心圆、矩形、椭圆、裁切、双 pad、侵入、倾斜、小尺寸反例 | 几何外圈仍可能是其他圆环物体 |
| 状态来自观察 | 无 checkpoint 转移表，无路线累计量，逐帧独立 | 没有时序跟踪、迟滞或穿门完成判断 |

硬化后的相关回归命令通过 170 项测试，覆盖对抗反例、新模块、现有深度扇区、感知质量/信任、
恢复、profiling、跨场景基线和非米制 motion。命令记录在 [perception HANDOFF](handoffs/perception-HANDOFF.md)。Ruff 对修改和新增的 Python 文件
检查通过。测试选择针对本次改动；未声称运行所有仓库测试或硬件/SITL 测试。

[当前报告](../examples/course-perception-hardened/report.json) 是一次 36 帧合成回放，分辨率为
320×240，固定随机种子 41 用于低光纹理，配置和源码哈希均随报告保存。单元测试另覆盖
160×120、320×240、640×480 和 480×240，线路横移约 -0.23 至 +0.22 图宽；pad 的大小、位置、
极性和物理距离分别变化。新增对抗测试还改变圆弧/阴影的尺度、位置和图像长宽比；阴影使用
dark polarity 检测器测试，防止默认亮线极性掩盖误检。CLI 当前报告使用同一默认 bright 配置。
这些离散点通过不等于整个连续范围均已验证。原 `examples/course-perception` 是 v1 历史快照。

实际观察边界如下。表中灰度对比度是合成线与背景的差，宽度计算使用测试内参 fx=224 px。

| 条件 | 实际结果 | 解释 |
| --- | --- | --- |
| 直线/一个 L 形转角，高对比度 | line confidence 1.000；通过 | 只支持可见连通路径，不解迷宫岔路 |
| 对比度 30、43 灰度级 | 线路拒绝 | 达不到配置的有效证据要求 |
| 对比度 45、90 灰度级 | 线路通过 | 这是本组合成图像的边界括定，不是曝光通用下限 |
| 两条平行线 | 原始 candidate 分数 1.000，有效 confidence=0，`detected=false` | 竞争候选不输出路径点 |
| 分叉线、严重断线 | 线路拒绝 | 不将两条分支的中点当作路径 |
| 低光，有纹理，线强度 50、背景随机 5–19 | line score 约 0.475 → 0.560，恢复成立；state 仍 degraded | 拟合一致性降低了最终重试得分；权限变化 NONE |
| 接近全黑、弱线强度 7、背景 3 | 重试后仍拒绝线路 | 亮度变亮不代表找回信号 |
| 全黑且深度全部失效 | recovery=false，depth invalid，clearance unknown | 保留双重退化理由 |
| 开口与被深度阻挡的相同开口 | 都有视觉候选；后者间隙拒绝 | 形状检测与可观察通过空间分开 |
| chicane 样例 | 探测平面宽度 1.0625 m；支持 | 未规划转弯或验证后续障碍 |
| 窄缝样例 | 0.2857 m；拒绝 | 低于默认需求 0.65 m |
| 72 列 / 74 列连续空间，z 探测=2 m | 0.6429 m 拒绝 / 0.6607 m 支持 | 验证内参和 envelope 实际参与估计 |
| 一个近距像素分割本来足够宽的通道 | 拒绝 | 扇区分位数不能掩盖局部小障碍 |
| 正常亮/暗 pad 外圈，深度 1.5 m | 检出，下降几何条件通过 | `candidate.safe` 仍为 false，动态/身份未评估 |
| pad 内一个 10×10 深度侵入物 | 拒绝平面与足迹条件 | 所有有效内孔点都参与残差检查 |
| 合成平面倾斜 30° | 拒绝 | 限制的是相对相机光轴角度 |
| 相同像素外圈，但 z=0.45 m | 拒绝尺寸条件 | 单凭外观圆环不代表够大 |
| 实心圆、明显椭圆、矩形门框、裁切外圈 | landing 拒绝 | 缺少合格外圈/内孔证据 |

初版的裁切圆弧误检已作为对抗回归保留：`synthetic:clipped_pad` 从约 0.615 降为拒绝；新增
partial_ring、curved_shadow、wall_edge、wall_highlight 在正确极性下原来均得 1.000，硬化后
全部拒绝，且不输出路径点。short_fragment 也拒绝。干净斜线保留支持，默认样例 confidence
约 0.951；L 形正例的宽转角行不参加直线拟合。有限几何检查仍不能识别地面语义，长半径
近直圆弧、局部墙上条纹和与真线同形的阴影仍可能无法区分。真实强弯线的召回率也会下降。

gap 合约现在将全三维可通行性固定为 UNKNOWN、supports_3d_traversal=false，所有 authority
change=NONE、executed=false。outside_roi_obstacle 与 beyond_probe_obstacle 反例中局部
宽度仍为 2.1786 m；这些通过测试的数值恰好展示为什么不能把局部支持升级为整机可通行。
深度过期则局部宽度和列区间也为空；缺标定在输入检查阶段直接拒绝，不产生 trace 事件。

RGB 中有紧凑阻挡结构、深度却远且平坦时，整体和所有内嵌 opening gap 均输出冲突疑似并拒绝
局部支持。相反，视觉门框加近距深度墙也不支持开口通过。该代理会保守拒绝部分平面涂装；
缺乏明显 RGB 结构的透明障碍、细杆或系统性深度错误仍可能漏过，不能把 unverified 当作一致。

另一个实测失败是暗纹理背景范围扩大到 5–29、线强度 50 时，CLAHE 提升整体对比度却制造
较多竞争连通区域，线路仍被拒绝。默认交付没有根据比赛坐标特判此图。线路恢复门限为当前
合成集的启发值，既可能漏检，也可能在未见纹理上误检。

当前一次 CPU 回放的 observe 延迟 p50=4.788 ms、p95=8.578 ms、max=17.562 ms；包括首帧
冷启动、输入哈希和阶段计时，不含磁盘写出。环境是报告中的 x86_64 CPU、OpenCV 5.0.0、
NumPy 2.5.2、Python 3.12.3、OpenCV 单线程。36 帧单次回放不是稳定吞吐测试，不与初版的不同样本集比较加速，不能据此外推
Orin、相机采集延迟、闭环控制频率或飞行安全。

还没有测得的边界包括：真实镜头畸变/标定误差、深度与彩色图配准误差、运动模糊、滚动快门、
彩色线与复杂地面、光斑/玻璃/反光深度、任意姿态开口、动态障碍、时间序列抖动和真实安装
遮挡。检测器对遮挡、横向路径、低分辨率小外圈和倾斜开口可能保守拒绝；固定的归一化
下部 ROI 也不是相机视角不变性。默认 envelope 不是已测整机尺寸。

window/return navigation 在结果 capabilities 中始终 unimplemented。感知模块不输出位姿；
复用栈里的 VisualDeadReckoner 仍只累计无尺度、归一化图像运动，x/y 不是米，vx/vy 不是米每秒，
不构成 metric VIO/SLAM。测试用相同比例、不同分辨率位移验证其无量纲性质。时间平移、frame
编号改变、穿插 pad 帧不会改变对抗图像的线路或间隙结果，没有路线/比赛时间转移逻辑。

后续应先用已录制且有标签的基本路线数据替换合成样例，分别统计线路检出/误检、开口
候选 precision/recall、深度局部有效率、间隙估计误差、恢复成功/伪恢复、落点拒绝原因分布，
并重新记录配置 provenance。window 与 return 仍保留为 stretch goal，不占用基本路线的验证。
