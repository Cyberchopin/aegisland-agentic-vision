12 个场景各启动一次全新的 PX4，结果都从 ulog 读取：

| 问题 | 结果 |
|---|---|
| FRD/NED 坐标系转换 | ✅ EuRoC 位姿经我们的转换后发 40° 航向，EKF2 读到 40.0–40.1° |
| ENU 陷阱 | 按 ROS 习惯发 ENU，EKF2 读成 50°（应为 40°）。PX4 只转换 ENU 位置、不转换四元数，源码 + SITL 双重确认 |
| 时间戳 | ⚠️ **不应答 TIMESYNC 时，PX4 静默地用到达时间替换我们的采集时间**（150 ms 延迟 → 0 ms）。应答后要约 70 s（500 个样本）才收敛；收敛后测到延迟约 100 ms，剩下的差距是 SITL 时钟速率伪影 |
| 方差 | 消息方差只能调高、不能低于 `EKF2_EVP_NOISE²`：发 1e-4 时实际用 0.01，发 1、25 时原样使用 |
| **`EKF2_EV_QMIN=0` 时会融合 quality −1** | ✅ **在 SITL 里复现了。** `QMIN=1` 时，quality 0 或 −1 都会在 0.4 s 内停止融合 |
| 1 m 跳变 | 拒收约 1 s 后 **EKF2 重置到跳变后的位置**（`no_aid_timeout_max` = 1 s） |
| **5 cm/s 的渐进漂移** | **全程融合，test ratio ≈0，EKF2 跟着漂了 1 m** |
| 降权（方差 1 m²） | 仍然跟随，只是慢一点 |
| 标记为 untrusted（quality 0 + `QMIN=1`） | **停止融合，不再跟随漂移**；约 5.8 s 后本地位置失效 |

**怎样标记"不可信"才能让 EKF2 拒收：**
- 必须设 `EKF2_EV_QMIN ≥ 1`，并发 quality 0。只增大方差不够。
- 重定位时 `reset_counter` + 1。
- 代价：没有其他位置源时，约 5 s 后进入 failsafe。所以"自动标记不可信"的阈值需要团队决定（见 §6）。

## 4. `track()` 从 0.8 ms 跳到约 8 ms：GPU 降频（订正昨晚的结论）

实验结果在 `cuvslam-stereo-MH_01_easy-20261024-104505-trackstep-*`：

| 实验 | `track()` p50（每 250 帧） | 解释 |
|---|---|---|
| 从第 0 帧开始 | 0.7 ms → 第 1250 帧起 4.8–6.4 ms | — |
| 从第 1300 帧开始 | 0.7 ms → 第 2550 帧起 3.4–6.0 ms | **跳变跟着"开始后的时间"走，不跟图像内容走** |
| 从第 2500 帧开始（只跑 5.6 s） | 全程 0.7 ms | 结束得早，来不及降频 |
| 节流到约 20 fps（实时速率） | **从第一帧起就是 4.2–8.2 ms** | GPU 从来没有升频 |

`nvidia-smi` 每 0.5 s 采样：开始约 7 s 后，GPU 从 **P2 / 2535 MHz 掉到 P5，SM 频率一路降到 210 MHz**；同期 GPU 利用率只有 4–5%。所以这是驱动的 DVFS（利用率低就降频），**不是 cuVSLAM 的工作负载**。

- 昨晚我说"三次运行都在同一位置出现 → 由工作负载引起"，这是**错的**：每次运行速度相近，所以"同一帧"其实也就是"同一时刻"。
- 地图大小（观测数约 280、landmark 数约 250）在跳变前后基本不变，也排除了地图因素。
- **含义：**
  - 昨晚的 0.7–0.9 ms 是 boost 频率下的批量回放数字，**不代表实时运行**；
  - 实时速率下开发机是 4–8 ms；
  - Orin 上必须固定频率（`jetson_clocks`），并按真实帧率测量。
- 帧号和时间的精确对齐没有做，但"节流后从一开始就慢"这一点足以区分两种假设。

## 7. 两个概念（用今天的真实数据）

### 概念 1：为什么渐进退化比跟丢更危险，以及我们怎么检测它

**跟丢是"响亮的失败"：**
- cuVSLAM 返回 `None`，我们发 quality −1，或者干脆不发；
- 0.4 s 后 PX4 自己停止使用视觉（SITL 中观察到 0.36 s），飞控知道"现在没有位置"，会进入 failsafe。
- 这条路径**每一层都知道出了问题**。

**渐进退化是"安静的失败"：**
- MH_01–05 两种模式下 cuVSLAM 一帧都没有跟丢，但在 MH_05 的暗段（亮度约 14/255）之后，误差从 0.09 m 涨到 0.21 m；
- 整个过程中，cuVSLAM 报告的状态一直是 tracking，它的协方差也不变大（AUC 0.28，甚至反向）；
- PX4 这一端更糟：在 SITL 里我们发了每秒 5 cm 的漂移，EKF2 的 innovation test ratio 一直是 0，它把漂移**当成真实运动全盘接受**，位置跟着走了 1 m。
- EKF2 只会拒收"突然的大跳变"，而且在视觉是唯一位置源时只拒收 1 s，之后就重置过去（1 m 跳变场景）；
- 所以渐进退化会**一路穿过 tracker 和 EKF2 两层防线**，直到飞机按错误的位置飞。

**我们怎么检测：** 不能问"出错的那个系统"自己（cuVSLAM 的协方差、点数都被证明没用），要找**独立的旁证**：
- 陀螺：短时间内很准，而且与相机无关。视觉算出的旋转和陀螺对不上，就说明视觉在乱估。这是今天在留出集上唯一稳定显著的事件信号（Stereo 4/4、Inertial 10/11，均 p≤0.01）。
- 另一个前端（VDR 的 ORB 匹配数）：它看到的"纹理有多少"能很好地给每一帧排风险（AUC 0.8）。
- 发现之后，要用 EKF2 **能执行**的方式告诉它：quality 0 加 `EKF2_EV_QMIN=1`（SITL 证明会停止融合），而不是只调大方差（证明挡不住漂移）。

**局限：**
- 这些信号的提前量很小（中位 0.3–1 s），更多是"及时发现"，不是"提前预测"；
- 唯一有 3 s 提前量的亮度只在一种模式里成立；
- 阈值来自 EuRoC 相机，换相机必须重新拟合。

### 概念 2：为什么"检出 10/11"可能什么都不说明——偶然基线

- 第一版结果里，"新 landmark 数"在训练集检出 14/15、"另一模式分歧"检出 12/15，看起来很好。
- 然后我把同一个信号整体平移 ≥15 s（这样它和误差事件已经没有任何时间关系），用同一个阈值再算：
  - "新 landmark 数"仍然检出 **11.1/15**；
  - "另一模式分歧"仍然有 **9.4/15**。
- 原因：
  - 一个事件的判定窗口是"起点前 3 s 到终点后 1 s"，至少 4 s，也就是 80 帧；
  - 而一个 5% 误报率的信号，平滑后是一段一段成片亮的，随便哪 80 帧里碰上一段的概率很高。
- 所以真正有意义的是"比偶然多多少"：
  - 陀螺残差在 Stereo 留出集是 4/4，偶然只有 1.2/4（p=0.005），这才算数；
  - 而 Inertial 的组合规则 11/11 看起来更漂亮，偶然水平却已经是 7.1/11。
- 同样的道理，逐帧 AUC 在单个序列上，平移后的 95 分位都能到 0.7–0.85。所以我只用多个序列合并后的 AUC 和它自己的偶然分布比。
- 今天这一步让 16 个信号里看起来"有用"的大部分降级成了"没用"或"不确定"，但剩下的结论是可以信的。
